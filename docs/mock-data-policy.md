# Mock Data Policy

## Purpose

This policy keeps public examples safe, generic, and easy to review.

## Allowed mock data

Examples may use:

- Placeholder names such as `Example Project`.
- Localhost URLs.
- Fake IDs such as `demo-001`.
- Generic issue titles.
- Sample dates that do not refer to real events.
- Small JSON files created only for documentation examples.

## Disallowed data

Examples must not include:

- Real credentials.
- Production service URLs.
- Real user records.
- Private repository history.
- Private prompts.
- Payment or entitlement logic.
- Internal deployment details.

## Review rule

A mock example is ready only when it can be understood without private context and can be verified from the public repository alone.

## Removal rule

Mock examples should be removable without affecting the rest of the repository.
